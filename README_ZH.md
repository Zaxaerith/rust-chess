# RUST CHESS

[English](README.md)

> 本地开发候选：**v0.2.5 PGN Library**（未发布），详见[验收报告](RELEASE_CANDIDATE_v0.2.5.md)。[v0.2.4](https://github.com/Zaxaerith/rust-chess/releases/tag/v0.2.4) 已正式发布。

一个用 Rust 编写的本地窗口国际象棋游戏。支持双人对战、人机对战、5 档 AI
难度、走棋动画、AI 思考停顿、开局结束动画、设置记忆，以及多套仿 VSCode
主题。v0.1.4 增加棋钟终局结算、带时间恢复的悔棋、明确的 AI 错误处理及回归测试。

## 功能

- 双人对战 / 人机对战（人机执白或执黑）
- AI 难度 5 档：入门 / 简单 / 中等 / 困难 / 大师
- 合法走法提示、将军提示、升变选择、王车易位、吃过路兵
- 悔棋、新对局、棋谱记录
- 走棋滑动动画、AI 思考停顿、对局结束结算面板
- 游戏设置记忆（保存到 exe 同目录的 `settings.cfg`）
- 分辨率/刷新率选项自动读取系统显示模式
- 10 套主题：Dark+ / Light+ / Monokai / Solarized / Nord / Abyss / Kimbie Dark / Quiet Light / Tomorrow Night Blue / Red
- 11 种语言：简体中文、繁體中文、English、Français、Español、Latina、日本語、한국어、Deutsch、Italiano、Русский
- 5 套棋子：CBurnett / Merida / Chessnut / RhosGFX / Fantasy
- 6 套棋盘：Classic / Walnut / Ocean / Emerald / Marble / Graphite
- 玩家执黑时可选择自动翻转棋盘
- 对局中可请求基于 Pleco 搜索器的决策建议
- 左侧纵向主菜单与动态旋转齿轮 Logo
- 三级棋盘设置：界面设置 / 对局行为 / 棋钟
- 棋子拖拽、拖动放大、圆形或方形落点标记
- 预走棋、自动升后、着法确认和两种王车易位输入方式
- 本地 10 分钟棋钟、临界时间提示、十分之一秒显示和给对方加时

着法确认和升变选择期间继续计时；菜单和设置页面暂停计时。悔棋恢复目标历史局面保存的双方棋钟，人机回复后退两手。加时不能恢复已结束对局。当前所有本地对局均属休闲对局，因此“仅限休闲”和“总是”均允许相应操作。根目录 EXE 为历史构建，本候选版本请运行新编译的 target/release/chess_rust.exe。

## 直接运行

项目根目录的 `国际象棋.exe` 是完整可执行文件，棋子素材已嵌入 exe，
双击即可运行，不需要额外安装任何东西。

## 从源码编译

需要 [Rust 工具链](https://www.rust-lang.org/tools/install)（stable 即可）。

```powershell
cargo build --release
```

编译产物位于 `target/release/chess_rust.exe`，可以复制到任意位置直接运行。

## 技术栈

- `minifb`：本地窗口与输入
- `shakmaty`：国际象棋规则引擎
- `chasolver` / `chess`：超时将死可能性判定（MIT），不替换对弈 AI
- `pleco`：人机对战的 AI 搜索器（Rust 重写的 Stockfish）
- `png`：棋子 PNG 解码
- `ab_glyph`：文字渲染（使用系统中文字体）

## 棋谱、存档与复盘（v0.2.0）

- 主菜单“打开棋谱”通过原生文件对话框读取单盘 UTF-8 PGN。v0.2.4 起完整验证并保留嵌套变化、注释和 NAG；着法只读，注释可在内存副本编辑。上限为 4 MiB、每路径 4096 半回合、64 层 RAV、所有分支累计 8192 个着法节点。多盘请使用棋谱档案馆；“打开棋谱”仍要求单盘。非标准变种与非法分支明确报错。

### Advanced PGN Replay（v0.2.4）

- 首步/上步/下步/末步和 Left/Right/Home/End 沿当前选定路径导航。在岔口点击“选择变化”查看当前局面的候选；若要替代已走的一着，先退回其父局面。长路径/候选列表可滚动。“上级变化”回到最近岔口，“回主线”恢复进入分支前记住的主线位置；节点、SAN、回合编号、NAG、注释对应当前路径。
- “播放/暂停”只移动 Replay，速度为 0.5×/1×/1.5×/2×/3×/4×，默认约每秒一半回合。手动跳转、切换分支和编辑会暂停，终点自动停止。延迟帧最多补进 2 秒/8 着，不开自动落子线程，不推进棋钟，也不保存活跃播放任务。
- “注释”默认编辑着后注释；“着前/着后”也可编辑棋局或变化首着前的注释。归属约定：开局前文字归 root，RAV 首着前文字归该首着 before，其余归前一着 after，导出不使用私有扩展。单条编辑上限 4096 UTF-8 字节，拒绝花括号与不安全控制符，可粘贴 CR/LF/tab。Enter 应用，Escape 取消编辑，Ctrl+A 全选，Ctrl+V 粘贴，方向键/Home/End 按 Unicode 字符移动光标。“清除”删除当前节点的文字注释，NAG 模式则清除 NAG。
- “NAG”编辑有序、空格分隔的 `$0`…`$255` 或 `! ? !! ?? !? ?!`。每节点最多 64、全树最多 65536，重复值与顺序保留。注释窗口明确标为片段，可用上下按钮翻看，底层数据不会截断；导入源文件不会被自动修改。
- 未导出修改显示状态，返回、替换 Replay 或点击窗口关闭按钮前，可取消、导出后离开或明确放弃。保存对话框取消或写失败不会放行退出或清除改动。编辑仅在内存，须导出保存；强制结束进程不能从自动存档恢复这些注释。
- Replay 的“导出 PGN”保存完整注释树、嵌套 RAV、文字、NAG、标签、SetUp/FEN 和结果。往返保证语义一致，不保证空白或符号原拼写。实时棋局的普通线性导出保留。分号注释规范化成花括号；无法安全表示的含花括号注释和 `%` 逃逸行明确拒绝。注释内图形指令按文字保留，不解释为画图。
- 总注释最多 1 MiB、条数最多 16384（含空注释）。树预算按每节点 2048 字节加文字/条目/NAG 的保守额度计费，上限 24 MiB，不把它冒称整个进程 RSS 上限。多盘管理使用 v0.2.5 棋谱档案馆，仍无变化创建/重排功能。
- 本版明确禁用变化节点的单点 UCI 分析。Game Review 仍由同一引擎分析原线性主线；分支中标明“仅主线分析”，隐藏主线曲线游标、质量和评分覆盖，返回主线恢复联动。只改注释不改变 Review 缓存身份或重新搜索，不为分支另开引擎。
- v0.2.4 历史 CLI/Mock/离屏证据及其未测的原生对话框、窗口关闭、真实引擎交互边界见 [v0.2.4 报告](RELEASE_CANDIDATE_v0.2.4.md)。本轮无 Computer Use 或本地 ZIP。
- 对局顶部提供“导出 PGN / 复盘 / 复制 FEN / 导入 FEN”；终局后仍可导出和复盘。取消文件对话框不改变棋局。
- 复盘支持首步、上一步、下一步、末步按钮，可滚动并点击着法；Left/Right/Home/End 浏览首尾及前后局面。返回后继续原来的实时棋局或主菜单。复盘不改真实历史、不扣时间、不消费后台回复，也不覆盖自动存档。
- FEN 必须完整包含六字段。使用粘贴按钮或 Ctrl+V；Ctrl+A 清空输入，方向键和 Home/End 移动输入光标。FEN 建立独立局面并重置棋钟、历史和重复记录，不等同于完整存档恢复。
- 自动存档位于 `%LOCALAPPDATA%\RUST CHESS\autosave-v1.json`。格式版本为 1，保存初始 FEN、完整着法、双方棋钟及快照、模式/偏好和终局原因。使用 SHA-256 校验、临时文件、安全替换和 `.json.bak` 备份。坏存档或未知版本会报错并保留；人工修复前请先复制备份。失败写入留下可恢复 `.tmp` 文件，不删除用户数据。
- 每次正式落子、悔棋、加时、终局、菜单/正常退出时保存，进行中的棋局另每五秒保存一次。离线时间不扣钟。启动发现未完成对局时可选择“继续 / 新局 / 暂不恢复”；不会静默覆盖运行中的另一棋局。
- 文件对话框和 FEN 输入期间暂停棋钟。重复存档错误首次弹窗，关闭后保留失败标记。自动存档只保留最近棋局；长期归档请导出 PGN。
- 测试可用 `RUST_CHESS_DATA_DIR` 隔离存档；正常设置仍使用原 `settings.cfg` 路径与键名。
- 打包使用 `./package.ps1`，需 Python 3.11+ 收集并核实锁定依赖的许可证。已有发行目录/ZIP 不会被覆盖，测试工具、配置、用户存档和测试棋谱不进入发行包。

对于已发布的 v0.2.0，Pleco 0.5.0 的历史 MIT 原件已与发布源码提交核实，随包保留固定来源及校验记录。该版本的用户验收与包证据保留在历史 `RELEASE_CANDIDATE_v0.2.0.md`，不冒称为 v0.2.1 验收结果。报告不进入 ZIP，以免引用自身归档哈希。新的正式发布仍须单独授权。

## Analysis Board / 可选的外部 UCI 分析（v0.2.2）

- 打开“UCI 分析”，选择自行安装的本地 `.exe`，再手动“启用引擎”。支持空格和 Unicode 路径，以引擎所在目录作为工作目录，支持相邻 NNUE 文件。不下载、不捆绑引擎，加载偏好不会自动执行。
- “分析当前局面”针对实时棋盘或 Replay 游标，发送真实初始 FEN 和着法前缀。显示白方视角评分、深度、合法 SAN 最佳着法及完整编号 PV；`M+3` / `M-3` 分别表示白方 / 黑方可在 3 回合将杀，`M+0` / `M-0` 区分已将死黑方 / 白方，`>=` / `<=` 表示评分边界。不同引擎的 cp 标定不等同于统一胜率。
- 默认 2 线程、64 MiB Hash、1000 ms、MultiPV 1。按钮循环设置有界时间/线程/Hash（100–10000 ms、1–8、16–256 MiB）；改变这些资源参数会关闭当前引擎，需重新启用。MultiPV 可选 1/2/3，修改时安全停止、同步、配置并重新分析，不重启引擎；不支持 MultiPV 时明确退回单线，引擎声明的范围也可能限制实际条数。只设置引擎声明支持的 spin 参数，并按其范围限幅；不支持时显示降级提示并使用引擎默认值。
- “停止分析”取消真实搜索，“关闭引擎”回收进程。落子、悔棋、导入及复盘跳转使旧结果失效。必须消费 stop 对应的 bestmove 才可开始下一搜索，超时则关闭引擎。分析不落子、不暂停实时棋钟，也不替换 Pleco 五档对弈；Replay 的只读停钟规则保留。
- 独立 JSON 偏好文件 `analysis.cfg` 位于 `%LOCALAPPDATA%\RUST CHESS` 的存档旁（QA 可隔离），仅保存路径和资源设置，不保存启用许可，不进入自动存档 JSON。原 `settings.cfg` 保持兼容。
- 只选择并运行您信任的引擎；本功能不是第三方程序沙箱。没有引擎配置仍可正常对弈、存档和复盘。本轮真实引擎、窗口测试证据及限制单独记录在 `RELEASE_CANDIDATE_v0.2.2.md`；没有进行真实 Stockfish 或 v0.2.2 UI 人工验收。
- 验收采用 CLI / Rust 自动化优先，使用受控 Mock UCI 进程，不依赖 GUI 自动操作。分析测试运行 `cargo test --locked -j 2 uci_tests`；许可证/检出回归运行 `python -B -m unittest discover -s tools -p test_collect_licenses.py`。真实 Stockfish 与完整 UI 人工验收单独记录，不从无界面测试推断通过；长期约定保存在 `AGENTS.md`。

- 纵向评分条与当前候选箭头仅供阅读。正值始终有利白方，翻转棋盘也不改变含义。白色占比采用 `0.5 + atan(clamp(cp,-4000,4000)/400)/pi`，是有界可视化，**不是获胜概率**；将杀使用端点，边界分数保留 `>=` / `<=`。无有效分数时显示中性条及 `—`。
- 点击已收到的候选行切换其评分与箭头。每行显示排名、自身深度、评分及带回合编号的 SAN，已收到 / 实际配置数量不会虚构未到达的候选。长文本换行并明确省略，数据模型仍保留每线最多 128 半回合、最多 3 线。仅在 PV 更新时于临时局面逐手验证和缓存 SAN。非法 PV 停在错误半回合，显示错误并禁用该线的评分和箭头。
- PV 是预测，不能视为玩家已走棋谱。MultiPV 共享原有时间预算，多线可能降低搜索深度。落子、悔棋、导入、Replay 跳转/退出、取消及引擎变化会统一使所有候选失效。旧 `analysis.cfg` 无 `multipv` 字段时默认为 1。仅支持标准国际象棋，暂不提供 UCI_Chess960 或任意引擎参数编辑器。

## Game Review 整盘复盘（v0.2.3）

1. 打开单盘 PGN，或进入本地棋局的 Replay。在“UCI”页签中自行选择并明确启用可信外部引擎。
2. 打开“整盘复盘”，检查范围与预计搜索预算，再开始。默认每局面 500 ms、前 160 半回合（最多 161 局面，约 80.5 秒加协议等开销）、MultiPV 1。时间可选 100/500/1000/2000 ms，范围可选 40/80/160/320/512 半回合；线程/Hash 沿用当前启用引擎的配置，默认 2/64 MiB。长棋谱明确显示只分析前缀，不冒称全局完成。
3. “暂停”安全停止当前搜索，保留已完成局面；“继续”重试第一个未完成局面。“取消”保留部分成果并释放引擎给单点分析。暂停期间仍由整盘任务独占控制器，全程只有一个引擎进程，不逐局面重启，也不为手动分析另开进程。“已完成”表示指定范围处理结束，不表示每手都有充分证据可评价。
4. 分析时可继续浏览 Replay，任务目标是固定棋谱快照，不跟随游标。点击曲线上已分析点跳转；未知/非精确分数保留缺口，Mate 与主要失误独立标记。切换到 UCI 页签仍可用原 PV 界面，取消/完成整盘任务后可再手动搜索或改参数。退出 Replay 会取消任务，不改实时棋局、棋钟快照和原 PGN。

曲线是**白方视角的有界优势指标，不是胜率曲线**。采用 `A(cp) = 2*atan(clamp(cp,-4000,4000)/400)/pi`；白棋损失 `max(0,A(前)-A(后))`，黑棋反向相减。损失 ≤0.05 为 Good，≤0.15 为 Inaccuracy，≤0.35 为 Mistake，更大为 Blunder。Best 还要求实战与引擎合法建议一致且损失 ≤0.05。必须是两侧精确 cp、深度均 ≥10 且差距 ≤6；Mate 转换、终局、边界分数、缺少/低深度、未完成局面或“匹配最佳但评分矛盾”均为 Unrated。与建议一致的事实仍用 `=` 保留，不等于已证明绝对最优。这是预算受限的启发式，不是棋规或客观定理，不提供 Brilliant/Book 等标签。

缓存位于 `%LOCALAPPDATA%\RUST CHESS\review-cache-v1\<key>.review.json`（显式隔离的数据目录亦适用），与 `autosave-v1.json`、`settings.cfg`、`analysis.cfg` 和 PGN 分离。格式/校验和、完整初始 FEN+着法+结果标识、引擎 EXE SHA-256/名称/作者/路径、搜索配置、范围及算法版本共同防止串用结果。每完成 8 个局面，以及暂停/取消/完成/安全退出时原子保存，不按帧或每步写盘；单文件上限 1 MiB、最多 32 个缓存文件，不自动淘汰。重新打开同一 PGN、启用同一引擎并开始：完整缓存不再发送搜索，部分缓存只分析缺失局面。棋盘规则终局保存原因和标记，不伪造 cp。

清理缓存时，先退出程序，再手动移动/删除 `review-cache-v1` 中相应 `.review.json`，不要删除存档或 PGN。坏缓存报错并保留，内存分析仍可继续；数量满或不可写时明确报错，不删除历史。小型检查点采用批量同步原子写，慢磁盘可能短暂停顿。外部 NNUE/引擎配置文件不做指纹，更换后请手动清理相关缓存；EXE 指纹在既有 UCI 后台线程计算，文件上限 256 MiB。v0.2.3 验收没有下载/捆绑引擎，未完成真实 Stockfish 棋力/NNUE/资源测试或该版 UI 人工验收，Mock 与离屏证据分别见[报告](RELEASE_CANDIDATE_v0.2.3.md)。

### 棋谱档案馆（v0.2.5）

- 主菜单进入“棋谱档案馆”，点击“导入 PGN”，原生对话框每次选一个文件，该文件可含一盘或多盘；反复导入可追加其他文件。单个有界后台线程处理，显示已处理数量及成功、重复跳过、失败数量。遇首个非法棋局或归档写入错误即停止，报告盘号；先前已提交棋局保留，后续明确为未处理。UTF-8 损坏作为文件级错误，在归档前拒绝。
- 上限：输入/规范化多盘文本各 32 MiB、一次 200 盘、馆藏 2000 盘、索引 4 MiB。终止结果标记后至下一盘起始前的注释按前一盘尾注保留。每盘沿用 v0.2.4 的 4 MiB、每路径 4096 半回合、64 层 RAV、8192 节点及注释限额。逐盘验证完整树并归档，浏览列表只持有元数据。
- 目录为 `%LOCALAPPDATA%\RUST CHESS\library-v1\`；显式测试时使用 `RUST_CHESS_DATA_DIR/library-v1`。`index.json` 保存标签、收藏、时间和内容哈希，`games/<稳定ID>-<SHA256>.pgn` 保存可直接读取的完整注释棋谱。原始导入文件、autosave schema、设置、Review Cache 均不改。启动不扫描完整馆藏；进入页面读索引，打开选定一盘才读 PGN。
- 搜索支持白/黑棋手、赛事、日期和结果的大小写不敏感普通文本匹配，可叠加“仅收藏”和结果筛选。排序循环：最近导入、PGN 日期文本、棋手姓名、收藏优先。每页只画可见条目，滚轮或上下按钮滚动，长名字/赛事截断显示。点击搜索框输入 Unicode，Backspace 删一个字符，Ctrl+A 清空；Enter 结束输入，再按 Enter 打开选中棋局。
- “收藏/取消”只更新索引并跨重启保留。“打开复盘”完整保留分支、注释/NAG、自动播放和原有分析限制；返回时保留搜索、筛选、选择和滚动。Game Review 仍绑定原主线，馆藏 ID 和收藏不改变缓存身份，不触发引擎搜索。
- 馆藏 Replay 的“保存到馆藏”更新内部副本、元数据及哈希，稳定 ID 不变；普通外部或实时对局 Replay 的“加入档案馆”保存为内部副本并建立关联。“导出 PGN/导出副本”是另存独立文件，不更新馆藏；禁止导出到应用数据目录以免覆盖受管理文件。只有成功后才清除未保存状态，失败保留修改，仍使用唯一的未保存退出确认。成功导出副本也满足退出保护；若需更新馆藏，请明确保存到馆藏。
- 对完整规范注释 PGN 做 SHA-256 去重；完全相同跳过。同主线不同标签、注释、NAG 或变化分支保留为不同馆藏。保存后若会与另一条内容完全相同则报告冲突，不覆盖另一条。
- “移除”需确认，只操作选定内部副本和索引，不删除来源、自动存档或 Review Cache；没有自动淘汰、在线同步、批量清理或后台扫描。
- 写入先保存新 PGN 修订，再原子提交索引，成功后才移除旧受管理修订。异常中断可能留下未索引修订/临时文件，不静默删除。“检查/恢复”由用户明确触发，最多检查 4000 个目录条目，报告缺失/损坏或冲突修订，重新索引合法未认领副本。相同 ID/哈希冲突文件保留供人工检查。慢磁盘检查可能耗时，仅在已停真实棋钟的 Library 页面执行。
- 索引损坏/版本未知时不覆盖：先退出，人工备存并重命名 `index.json`，重新启动后点击“检查/恢复”，从合法 PGN 重建。PGN 本身无法恢复收藏和原导入时间。外部索引变化会在下次写入时拒绝，重启以重载；建议只运行一个写入实例，本版不提供多进程数据库事务。
- 仅标准国际象棋；暂不支持在线同步及一次多文件选择。自动化使用隔离目录和 Mock UCI，没有真实 Stockfish 或原生窗口自动验收，具体证据与人工待测项见 v0.2.5 候选报告。
